# Service understanding pilot: preregistration

Question: Does accurate rich documentation of an external service improve grounded decisions beyond basic schemas or the same facts in prose?

Seven arms: none, poor (types), moderate (assertions), rich (assertions + semantics + examples), prose (same rich facts), false (deliberately wrong units), stale (previous service version). False/stale arms measure robustness, not equivalent-information causal effects. The authoritative runtime contract never changes with documentation quality. All outputs use the same generic decision envelope and decoding settings.

Three synthetic service families: refunds (money units), scheduling (timestamp units), export (sensitivity and recipient restrictions). 24 tasks, five repeats, seven arms = 840 calls per model. Twelve development tasks and twelve test tasks; no test labels used to fit calibration. Family-shared contracts make this a within-family pilot, not unseen-service generalization. Ground truth is executable and researcher authored; no independent human verification is claimed. No real customer actions occur.

Models: Qwen3 4B Instruct and Gemma3 1B, independent hosted jobs. Neither is designated calibrated. Raw probability and a development-fit histogram mapping are compared on held-out tasks. A calibrated variant is a postprocessor, not a different foundation model. Jev requires real API access and is blocked if unavailable. Structured envelope validity is not evidence of semantic correctness.

Primary test contrast: rich-minus-poor correct candidate rate and safe task completion. Attribution control: rich-minus-prose. Secondary: false/stale degradation, invalid request rate, backend rejects, confident wrong rate, tokens, p50/p95/p99 wall latency. No retries in this first-action pilot. Outcome labels include abstention as incomplete on these answerable tasks. Bootstrap matched task clusters (repeat means per task), 2,000 resamples; synthetic families restrict inference to this corpus. Report raw denominators and failed/missing episodes. Brier/ECE are exploratory with only twelve held-out task clusters. No confidence score is claimed calibrated from one small pilot.

Blaze validates actual request/response bodies against the authoritative contract; never feed a rich arm a stronger runtime validator. IPC wall and native engine timing recorded separately. Fixture parity validation runs outside episode timing. One supplies versioned schema endpoints and digest checks; explicit pinned-versus-refresh version and outage probes separate from model effect. AlterSchema transformation + compiled cache study separate; annotations remain in model-context cache identity. Backend ownership, consent, amount/state correctness, version and idempotency enforced for every arm. Separate deterministic adversarial probes cover unauthorized requests, state races, duplicate writes and malformed responses.

Report must distinguish native/live measurements, local Python controls, model evidence, and blocked stages. Model API responses, request/document hashes, commit, model digest, settings and service gold are retained. No cloud inference, hidden paid keys, fabricated model confidence, or claims that schema fixes calibration.
